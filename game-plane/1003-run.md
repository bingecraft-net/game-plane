# 1003: Run

One command to subscribe to a repository of game servers on your bootstrapped infrastructure.

## Prerequisite

Bootstrap (story 1002) must have already run — Kind cluster, Argo CD, and the ApplicationSet controller must be in place.

## Run

After bootstrap, the CLI subscribes to a repository containing game server charts with one command:

```
gameplane run --repo git@github.com:user/game-server-manifests
```

## What Happens

1. **Repository cloned** — Game Plane clones (or fetches) the specified repository
2. **Subdirectories discovered** — Every subdirectory under `game-server-manifests/` is treated as a server chart
3. **ApplicationSets created** — An Argo CD ApplicationSet resource is applied to the cluster, referencing all discovered Helm charts
4. **Argo CD reconciles** — The ApplicationSet controller generates an `Application` for each subdirectory and reconciles them against the cluster
5. **Game servers start** — All game server software is installed/configured on the cluster
6. **Status** — surfaces Argo CD's reconciliation status through the CLI

## Helm Chart Repository

Server Helm charts live in the git repo specified at bootstrap time, under `game-server-manifests/`:

```
game-server-manifests/
├── README.md
└── <server-name>/
    ├── Chart.yaml          # Helm chart metadata
    ├── values.yaml         # Chart values (optional)
    └── templates/
        └── *.yaml          # Kubernetes manifests
```

Example:

```
game-server-manifests/
├── valheim-server/
│   ├── Chart.yaml
│   ├── values.yaml
│   └── templates/
└── monifactory-server/
    ├── Chart.yaml
    ├── values.yaml
    └── templates/
```

New subdirectories added to the repo are automatically picked up on the next `run`.

## Expected User Flow

```
gameplane bootstrap --inventory /path/to/local/inventory
gameplane run --repo git@github.com:user/game-server-manifests
gameplane status
gameplane debootstrap
```

## Acceptance Criteria

- [ ] One command subscribes to a repository and creates ApplicationSets for all discovered server subdirectories
- [ ] New subdirectories added to the repo are picked up on the next `run`
- [ ] World data persists outside the cluster lifecycle
- [ ] CLI reports game server status (running, stopped, error)
- [ ] Game servers can be stopped and restarted without data loss
